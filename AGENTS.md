# Инструкции для AI-агентов

## Перед началом

- Прочитай этот файл и `README.md`.
- Работай только в репозитории RIMLAB; не меняй исходный
  `onixframe-starter-landing` и сайт OnixFrame.
- Следуй тестовому брифу в README. Основной стек — HTML, CSS и JavaScript с
  Vite; не добавляй дополнительные библиотеки без необходимости.

## Структура и стиль

- Сохраняй разделение токенов, базы, компонентов и секций в `styles/`.
- Форматируй CSS читаемо: каждый селектор и каждое свойство с новой строки; не
  объединяй целый блок CSS в одну строку и не минифицируй исходники.
- Используй установленный Prettier и настройки `.prettierrc.json`; после
  изменения кода форматируй затронутые файлы.
- Используй CSS-токены и семантическую доступную HTML-разметку. Поддерживай
  клавиатуру, reduced motion и мобильное меню.

## Изображения

- Добавляй изображения для реального автомобильного сервиса только из
  утверждённых исходников или как явно обозначенные концептуальные иллюстрации.
  Не выдавай изображения за реальные выполненные работы RIMLAB.
- Если реальных фото пока нет, не заполняй портфолио выдуманными результатами.
  Оставь понятные места для фото «до/после» и сообщи, какие фото нужны.
- Не используй hotlink. Храни изображения в проекте, оптимизируй их и подготовь
  варианты/кадрирование для мобильного, планшетного и настольного экранов.
- Храни оригиналы в `assets/images/source/`, запускай `npm run images:process`;
  результат находится в `public/images/optimized/`. Используй `picture`,
  `srcset` и `sizes`: браузер подберёт размер и для обычных, и для
  Retina-экранов. Для отдельного мобильного кадрирования добавляй
  `<source media>` с мобильным вариантом. Указывай width/height, alt и lazy
  loading ниже первого экрана; не lazy-load главное изображение.

## Header и SEO

- Header остаётся прилипшим к верху во время прокрутки всей страницы на
  компьютере и мобильных устройствах. Обеспечь контрастный фон, достаточный
  z-index и якорные отступы.
- Настрой базовое SEO: уникальные title и description, canonical только после
  подтверждения домена, Open Graph, корректные robots.txt и sitemap.xml.
- Для RIMLAB не выдумывай реальные адрес, телефон, цены, сроки, гарантию,
  отзывы, рейтинг или структурированные бизнес-данные. Покажи, какие данные
  необходимо предоставить перед production.

## Форма и безопасность

- Форма собирает имя, контакт, диаметр дисков, цвет, ссылку на фото и
  комментарий.
- Сохраняй серверную проверку Turnstile, honeypot и безопасную обработку заявки.
  Секреты держи только в переменных окружения.
- Не показывай успех, если сервер не подтвердил отправку. Пока проект не
  настроен, честно оставь форму в демо-режиме.

## Правила изменений

- Не перезаписывай пользовательские изменения, не относящиеся к задаче.
- Не придумывай сведения о мастерской, которых нет в брифе.
- Для локальной разработки используй `npm run dev`, production-сборки —
  `npm run build`. Не запускай тесты, если пользователь не просил тестирование
  или проверку.
- В конце перечисли изменённые файлы, оставшиеся заглушки и данные, нужные от
  заказчика.

## Обработка изображений и форматирование

- После изменений запускай `npm run format`.
- Сохраняй оригиналы изображений в `assets/images/source/`; для отдельной
  мобильной композиции используй суффикс `--mobile` в имени исходника, например
  `hero--mobile.jpg`.
- После добавления/замены оригиналов запускай `npm run images:process`;
  подключай созданные варианты через `picture`, `srcset` и `sizes`, а мобильный
  кадр — через `<source media>`.
- Не подменяй отсутствующие реальные фото выдуманными примерами работ.
