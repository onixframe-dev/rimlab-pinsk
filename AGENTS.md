# Инструкции для AI-агентов

## Перед началом

- Прочитай этот файл и `README.md`.
- Работай только в репозитории RIMLAB; не меняй исходный `onixframe-starter-landing` и сайт OnixFrame.
- Следуй тестовому брифу в README и сохраняй стек HTML, CSS и JavaScript без лишних зависимостей.

## Структура и стиль

- Сохраняй разделение токенов, базы, компонентов и секций в `styles/`.
- Форматируй CSS читаемо: каждый селектор и каждое свойство с новой строки; не объединяй целый блок CSS в одну строку и не минифицируй исходники.
- Если в корне есть `.prettierrc.json`, придерживайся его настроек при форматировании. Сам файл настроек не устанавливает и не запускает Prettier.
- Используй CSS-токены и семантическую доступную HTML-разметку. Поддерживай клавиатуру, reduced motion и мобильное меню.

## Изображения

- Добавляй изображения для реального автомобильного сервиса только из утверждённых исходников или как явно обозначенные концептуальные иллюстрации. Не выдавай изображения за реальные выполненные работы RIMLAB.
- Если реальных фото пока нет, не заполняй портфолио выдуманными результатами. Оставь понятные места для фото «до/после» и сообщи, какие фото нужны.
- Не используй hotlink. Храни изображения в проекте, оптимизируй их и подготовь варианты/кадрирование для мобильного, планшетного и настольного экранов.
- Используй `picture`, `srcset` и `sizes` для подходящих форматов и размеров; AVIF/WebP с fallback — когда возможно. Добавляй width/height или aspect ratio, alt-текст, lazy loading для изображений ниже первого экрана. Не lazy-load главное изображение первого экрана.

## Header и SEO

- Header остаётся прилипшим к верху во время прокрутки всей страницы на компьютере и мобильных устройствах. Обеспечь контрастный фон, достаточный z-index и якорные отступы.
- Настрой базовое SEO: уникальные title и description, canonical только после подтверждения домена, Open Graph, корректные robots.txt и sitemap.xml.
- Для RIMLAB не выдумывай реальные адрес, телефон, цены, сроки, гарантию, отзывы, рейтинг или структурированные бизнес-данные. Покажи, какие данные необходимо предоставить перед production.

## Форма и безопасность

- Форма собирает имя, контакт, диаметр дисков, цвет, ссылку на фото и комментарий.
- Сохраняй серверную проверку Turnstile, honeypot и безопасную обработку заявки. Секреты держи только в переменных окружения.
- Не показывай успех, если сервер не подтвердил отправку. Пока проект не настроен, честно оставь форму в демо-режиме.

## Правила изменений

- Не перезаписывай пользовательские изменения, не относящиеся к задаче.
- Не придумывай сведения о мастерской, которых нет в брифе.
- Не запускай тесты, если пользователь не просил тестирование или проверку.
- В конце перечисли изменённые файлы, оставшиеся заглушки и данные, нужные от заказчика.
